# 审计外部 API 与授权清单

申请外部 API 权限时，先按部署启用的功能选模块，再到明细按**实际网关、方法、资源名和调用身份**核对。代码中有封装，不等于该环境会调用，也不等于已经获批。

详细路径见 [API 明细索引](../api/docs/README.md)；地址的默认值和覆盖方式见 [API Endpoint 环境变量](api_endpoints_env.md)。

明细已排除未使用的封装。只在特定版本或初始化任务中使用的接口单独标注；仓库外的部署脚本如果还有额外 API 调用，由对应负责人另行确认。

## 按业务模块选授权范围

| 审计模块                       | 依赖                                                                                                                      | 申请时要分开核对                                                                                                  |
|--------------------------------|---------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------|
| 数据接入、清洗、检索、策略     | [BKBase V3/V4、BKLog](../api/docs/data-platform.md)                                                                       | 数据源／结果表个人权限、采集和存储管理、Flow、SQL 查询。BKBase V4 环境仍可能使用共用 QuerySync 和兼容的 V3 入口。 |
| 权限判断、权限申请、人员与组织 | [IAM V3/V4](../api/docs/identity-and-workflow.md#bk_iam_v4)、[用户管理](../api/docs/identity-and-workflow.md#user_manage) | 运行时鉴权、资源回调、模型同步是不同职责。多租户平台调用还依赖用户管理查租户虚拟用户。                            |
| 应用信息、审批、处置、消息     | [PaaS、ITSM V3/V4、SOPS、CMSI](../api/docs/identity-and-workflow.md#bk_paas)                                              | 按所用审批版本与存量流程、标准运维模板和发送渠道申请；运行态与系统初始化分开。                                    |
| 监控、报表和扩展功能           | [BKMonitor、BKVision、BKSEC、水印、AI Agent](../api/docs/operations-and-ai.md)                                            | 按部署功能开启情况申请；监控上报通道与告警 API、Agent 各网关、BKSEC 发单插件分别核对。                            |
| SDK、直连和外部系统回调        | [特殊链路](../api/docs/direct-integrations.md)                                                                            | IAM SDK 权限、IAM 模型维护、入站回调、业务配置的 HTTP Pull 和 API 工具目标不由常规网关清单自动覆盖。              |

## 提交申请与验收

1. 确认环境、租户、应用 appcode、网关名和 stage。以目标部署的非敏感配置为准，记录使用的 IAM、BKBase、ITSM 版本，以及实际开启的扩展功能。
2. 从明细挑出该部署需要的接口。按 `网关 + stage + HTTP 方法 + 网关资源名` 去重，逐项标明用途、调用身份、租户范围和负责人；审批材料不填写
   token 或 secret。
3. 个人态确认真实用户是否能被上游识别，以及上游是否过滤该用户能访问的资源；平台态确认由哪一侧校验目标资源权限。应用获批和业务用户有权是两层独立检查。
4. 联调时至少对照一组有权限／无权限身份，验证租户头进入正确租户。模型写入、采集修改、发单等写接口在约定的测试资源上验证后再放量。记录授权单、环境、结果和未验证项。

申请记录可用以下字段：`环境｜租户｜模块｜网关/stage｜方法/资源名｜调用 appcode｜个人/应用/平台身份｜用途｜负责人｜授权状态`。

## 优先与负责人对齐的点

- **BKLog／采集**：业务列表已按用户调用，后续拓扑、主机和集群选择仍走租户管理员，确认由 BKLog 透传用户鉴权，还是审计先按目标业务鉴权。上报
  Token／Host 是平台态，不能用 `use_admin_username=False` 判断为个人态。[接口明细](../api/docs/data-platform.md#bk_log)
- **BKBase／策略**：个人列表和平台查询需要不同的边界；结果表样本预览走共用
  QuerySync，应明确策略权限是否足够，还是要另查目标表查询权限。[预览代码](../services/web/strategy_v2/resources.py#L2151) · [QuerySync 入口](../services/web/bkbase/query.py)
- **BKBase V3／平台接口**：多租户网关头用租户管理员，但部分请求的业务参数仍填平台账号。先确认上游按哪个字段判权，避免一个请求里出现两个身份。[请求构造](../api/bk_base/default.py#L67)
- **IAM／部署**：V4 常规 API 按实例租户调用；共享回调令牌读取和模型同步按注册租户（默认 `system`）。运行态不因为启用了 IAM V4
  就必须申请模型写入权限。[专项说明](../api/docs/direct-integrations.md#iam-v4-模型同步)
- **ITSM V4／SOPS**：SDK 平台态与租户管理员是两回事。确认各环境可接受的调用 appcode、平台凭据及流程专属
  Token，不按个人态统一处理。[接口明细](../api/docs/identity-and-workflow.md#bk_itsm_v4)

以上是代码盘点和授权建议，不是线上已授权清单。新增或改动出站接口时，同步维护明细，并标注单／多租户差异、实际调用入口及凭据类型。
