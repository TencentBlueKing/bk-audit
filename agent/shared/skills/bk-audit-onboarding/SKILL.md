# 项目上手与能力选配

根据用户场景准备所需能力，再交给具体任务技能。公开来源和诊断要点随本包提供；项目源码不是形成选配计划的前提。内部资料、凭据和个人环境参数不进入公开材料或外部查询。

## 1. 明确场景并诊断已有环境

读取用户本次目标、角色、Agent 客户端和已有授权；按 [能力清单](references/capabilities.md) 检查本次可能需要的工具、MCP 和 skills。复用已提供的环境信息，仅核实影响选择的缺口。

没有源码也可完成诊断和选配计划。已有源码时从当前目录或用户给定路径确认各仓库根和适用指引；技能安装目录不能代替产品 checkout。不扫描无关个人目录，不为准备计划先行 clone 或安装。

## 2. 给出按需选配计划

对照当前场景区分必需、可选和暂不需要的能力，说明用途、已有状态、可信来源及版本/路径、拟采取的动作和验收方式。已可用的能力直接复用；来源或版本未核实时列为待核实，不编造安装命令。

工具、MCP 接入和 skills 分别选择。技能中的链接是导航或使用前提，不表示其他技能会自动加载、依赖会自动安装，或服务已授权。

## 3. 按授权准备与验收

按当前请求执行获准的步骤。常规只读诊断无需逐项确认；安装或升级、修改客户端/项目配置、认证接入和外部写入，须确认相应动作、范围与目标，已有明确授权无需重复询问。缺少授权时保留计划，继续不依赖它的工作。

使用所选来源的当前说明和客户端实际支持方式，不预设 MCP 别名或参数。凭据由用户在客户端或本地安全配置中处理，技能包和报告不保存秘密。

分别验收“技能可发现、工具可调用、MCP 已连接及所需只读权限可用”，记录证据和未完成项；安装成功不等于已连接或已获得写权限。低风险版本查询、文件读取或获准的服务只读查询不能替代任务本身的业务验收。

## 4. 进入日常任务

返回简短的环境结论、所选能力及必要/可选理由、准备或待办动作、验收结果和下一任务入口。只交接当前任务所需技能，确认运行器可用后按该技能的场景 SOP 执行，不在 onboarding 展开其完整流程。

实际开发、构建、测试或提交前再取得相应源码和工程配置；缺少前提就说明具体受影响步骤。能力目录维护从已确认仓库的 `agent/README.md` 进入 `agent/architecture.md`。
