# 项目上手与能力选配

帮助用户具备完成当前任务的条件，再交给具体任务技能。公开能力和准备依据随本包提供；没有产品源码也可先形成选配计划。

## 1. 确定本次需要完成的工作

从用户目标、角色、Agent 客户端和已有环境判断本次范围，复用已提供的信息，仅询问影响选择的缺口。已有 checkout 时读取根及所需端内 AGENTS，从 `agent/README.md` 定位当前维护源；安装目录不能代替产品根。

已有环境能完成任务时，直接进入对应技能。流程咨询先读取实际规则；新 worktree 只核对指引和本次能力是否可用，不默认重新安装或接入全部服务。

## 2. 按需选择能力

读取[能力清单](references/capabilities.md)，分别判断 skills、工具与运行环境、MCP 接入。对本次需要的能力说明用途、已有状态、可信来源、准备动作与验收方式；可选项说明何时才需要，不要求安装整套能力。

涉及团队内部流程时，先查已接入技能或已有本地扩展入口；来源未知时向用户询问内部 onboarding 或维护源，不猜地址、不扫描个人目录。取得确认来源后交给其 onboarding，公开能力可独立继续。

区分未核实、缺少技能、工具不可用、连接缺失和权限不足。技能中的链接只表示来源或执行前提；读取技能、安装技能和连接服务分别核实。实际开发、构建或测试前，再取得当前产品源码和对应工程配置。

## 3. 准备所需条件

按当前请求已授权的范围准备；已有明确授权无需重复确认。技能安装、更新与卸载统一使用 `npx skills`，按目标客户端和使用范围选择项目级或用户级安装；已有可用技能直接复用。来源选择、同名技能及新 worktree 的核对见[技能使用与工作区要点](references/workspace.md)。

工具与 MCP 按各自来源及客户端实际支持方式准备，不固定别名或参数；认证在客户端或本地安全配置中处理。只处理本次需要的能力，内部资料、凭据和个人环境参数不进入公开材料或外部查询。

## 4. 验收并进入任务

分别检查所选技能能否发现并读取、工具能否调用、所需连接与只读权限是否可用。需要验证客户端发现时，从实际使用的目录启动新会话，用不提示技能名的任务检查路由；只做路径检查时如实说明覆盖范围。

返回简短的环境结论、已完成准备、具体缺口和下一任务入口。缺少连接时继续可完成的源码、分析或本地材料工作；环境就绪不等于业务验收完成。提交、发布、上传或通知按后续任务的实际授权执行，不为接入验收发送测试消息。
