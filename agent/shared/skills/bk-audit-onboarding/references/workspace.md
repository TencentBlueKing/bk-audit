# 技能使用与工作区要点

仅在安装、更新、发现故障或新 worktree 需要核对时读取。已有环境的普通任务直接进入对应技能。

## 使用 npx skills 维护

技能按标准 skill 包使用，安装、更新与卸载统一交给 `npx skills`。先确认可信来源、技能名称、目标客户端和安装范围；已可用的技能直接复用。命令与版本要求以[官方说明](https://github.com/vercel-labs/skills/blob/main/docs/commands.md)为准，无需另建安装或链接工具。

例如，在需要项目级安装的项目根目录，从已确认的产品源码安装本技能：

```bash
npx skills add ./agent/shared/skills/bk-audit-onboarding --agent codex
```

此处 `codex` 仅为示例，按实际客户端选择。需要用户级复用时使用 `--global`；项目级安装面向当前项目。安装前核对同名技能及已有来源，避免覆盖职责不同的技能；按需选择，不默认使用全选或跳过确认参数。

`npx` 可能下载并执行包，安装或升级按当前授权进行。安装结果不保证直接链接原始源码；源码变化后，按 CLI 的实际方式刷新所需技能，并重新核对内容。项目规则始终以当前 checkout 的 AGENTS、工程配置与 `agent/` 维护源为准。

## 来源与工作区

- 团队根及端内 AGENTS 随 checkout 维护；技能安装目录不是产品根，不据此推断源码版本。
- 根目录 `.agents/README.md` 若已有扩展来源登记，可直接复用其入口；也可从 `npx skills list` 或当前项目 `skills-lock.json` 核对已有安装来源。本地来源可读时直接查阅所需流程，锁文件中的相对来源按其所在项目目录解析。需要团队流程而来源未知时，先询问内部 onboarding 或维护源，不猜测私有地址，不要求先生成登记文件或准备整套技能链接。
- 补充来源按各自 onboarding 选择所需能力。内部流程及地址留在内部来源，公开 checkout 无内部源仍可独立使用。
- 新 worktree 取得当前基线的指引，核对本次所需技能是否可见、来源是否适用；缺少时再通过 `npx skills` 按所选范围准备。复用已确认的来源信息即可，不共享整份 `.agents`、认证或运行配置。Codex 从根启动不会自动发现端内安装的技能；跨端共用技能可安装到产品根，端内技能从对应目录使用，根会话则沿端内指引按需读取。
- 项目级安装与本地来源登记保持 Git 忽略；安装前核对当前规则覆盖实际输出及 `skills-lock.json`。业务测试资源按所属端工程规则另行隔离。

## 验收

核对所选技能的名称、来源、安装范围和实际内容，再从本次使用的目录检查客户端能否发现并读取。需要真实会话验证时，用不提示技能名的任务检查是否进入实际维护源；仅做文件或路径核对时明确说明。其他客户端按其实际规则验收，不将一种客户端的结果推广为通用兼容。

技能可发现、工具可调用、平台连接及业务结果分别记录；本地安装不代表服务已连接或已获准写入。
