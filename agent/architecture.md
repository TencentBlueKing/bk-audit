# Agent 协作架构与维护

## 目录职责

所有 Agent 专属导航、技能和辅助工具归入仓库根 `agent/`。

```text
agent/
├── README.md                 # 按 shared/backend/frontend/维护 路由
├── architecture.md           # 本架构与维护规则
├── shared/
│   ├── README.md             # 跨端能力与外部来源
│   └── skills/              # onboarding、提交、版本日志
├── backend/
│   ├── README.md             # 后端工程来源与领域能力
│   ├── skills/              # IAM、AI 评估
│   └── tools/commit-message/ # 后端标题校验及可选消息生成
└── frontend/
    └── README.md             # 前端工程配置入口
```

根 README 说明项目用途、适用范围和整体结构，并给出主要入口；Agent 入口和范围 README 帮助选择能力，可补充必要的概述与跨层指引；SKILL.md 写触发条件、前提、操作与产出；长示例、数据格式和清单放在该技能的 references/assets。脚本由实际消费方的 tools 或技能 scripts 维护。没有内容时不建空目录或重复索引。

## 探索与维护

`bk-audit-onboarding` 是轻量入口：探索任务读导航，维护任务读本规范；详细目录规则只在本文件维护。

| 变化 | 更新位置 |
| --- | --- |
| 调整仓库级分类或责任边界 | 本文件与根 README 的范围路由 |
| 新增、改名或删除技能 | 所属范围 README、技能正文及全部实际入链；删除不再使用的旧路径 |
| 修改技能行为或前提 | 该 SKILL.md；必要的 references、assets、脚本和回归一起更新 |
| 工程命令、hook、标题规则或测试入口变化 | 先改实际工程配置及其原有开发文档，再核对消费它的技能；不复制第二套规则 |
| 移动脚本 | 配置、调用方、文档示例和测试定位同步更新；运行最小离线入口检查 |
| 引入外部能力 | 在所属范围记录用途和上游来源，核对许可、触发与副作用；不复制上游正文 |

前后端构建、测试、lint、提交配置仍以 `src/` 的实际工程源为准。后端标题校验源码在 `agent/backend/tools/commit-message`，配置入口为 `src/backend/.pre-commit-config.yaml`；前端使用自己的 commitlint 和环境。

## 引用方式

- 导航通常按根 README、范围入口和具体技能展开；帮助理解整体架构或完成任务的概述、跨层引用可以保留，避免重复维护整套执行步骤。
- 技能之间确有执行依赖时直接引用，例如版本准备使用提交技能。文件格式可引用所属 SKILL 的规范章节，避免两处定义分支或校验规则。
- onboarding 和具体技能可按需要引用概览、维护规范或关联能力；链接应说明用途，单独安装时仍能定位当前 checkout 的权威来源。
- 目录移动后修正所有实际链接、代码格式路径、配置和测试；不保留只有跳转作用的过渡文档。

## 验证与公开边界

维护后检查：根入口能到达所有活跃技能；概述和交叉引用有明确用途、没有重复的规范正文或无效绕行；Markdown 链接与锚点可解析；配置和脚本入口实际存在；旧路径已移除；发布日志使用 `release-{版本号}-notes`；单一规范的消费方与其一致。脚本移动需验证其离线调用和范围判断，导航存在不等于业务验证通过。

公开材料不引用内部仓库、平台地址、真实业务样本、人员、认证或个人环境参数。内部仓库可以按产品 checkout 路径引用公开规则，只维护真实内部差异；跨仓库引用先确认各自根目录，不假设固定相邻路径。会话过程、测试记录与临时运行配置不进入长期入口。
